# CORE-MATH → PureLibm Translation Notes

Patterns and conventions for porting functions from
[CORE-MATH](https://core-math.gitlabpages.inria.fr/) to PureLibm.

## Bit-level representation

| CORE-MATH | PureLibm |
|-----------|----------|
| `b32u32_u u = {.f = x}; u.u` | `purelibm_f32_to_bits(x)` |
| `b64u64_u u = {.f = x}; u.u` | `purelibm_f64_to_bits(x)` |
| Type-punning union (`union {float f; uint32_t u;}`) | `memcpy`-based conversion in `src/utils/ieee754.h` |

PureLibm never uses pointer-cast or union-based type punning. All float↔uint
conversions go through `memcpy` (see `purelibm_f32_to_bits`, `purelibm_f32_from_bits`,
etc.). This avoids strict-aliasing UB.

## Fused Multiply-Add

| CORE-MATH | PureLibm |
|-----------|----------|
| `__builtin_fma(x, y, z)` | `fmaf(x, y, z)` for f32, `fma(x, y, z)` for f64 |

PureLibm uses standard C99 `<math.h>` FMA functions. The build system explicitly
disables `-ffp-contract=fast`; FMA semantics are expressed only through `fmaf()`
and `fma()`. See `src/utils/math_util.h` for the `purelibm_fma_f32`/`purelibm_fma_f64`
wrappers used throughout the library.

## Branch hints

| CORE-MATH | PureLibm |
|-----------|----------|
| `__builtin_expect(cond, 0)` | Removed |

PureLibm does not annotate branch probabilities. The target audience is
human readers of numerical algorithms, not branch-predictor tuning.

## Floating-point environment pragmas

| CORE-MATH | PureLibm |
|-----------|----------|
| `#pragma STDC FENV_ACCESS ON` | Not used |

Compiler support for `FENV_ACCESS` is unreliable (GCC bug #34678).
PureLibm uses `-fno-fast-math -ffp-contract=off` at the build-system level
instead, and does not change rounding modes at runtime. Testing is done
exclusively in round-to-nearest-even (see ADR 001 §4.1).

## Compiler-specific diagnostic suppression

| CORE-MATH | PureLibm |
|-----------|----------|
| `#pragma GCC diagnostic ignored "-Wunknown-pragmas"` | Not needed |

PureLibm's own source does not use pragmas that trigger unknown-pragma warnings.

## Exponent and mantissa extraction

| CORE-MATH (inlined) | PureLibm (`src/utils/ieee754.h`) |
|---------------------|----------------------------------|
| `(u.u >> 23) & 0xff` | `purelibm_f32_exponent_bits(x)` |
| `u.u & 0x007fffff` | `purelibm_f32_mantissa_bits(x)` |
| `u.u & 0x80000000` (sign check) | `purelibm_f32_sign_bit(x)` |

All IEEE 754 bit-field extraction is centralized in `src/utils/ieee754.h`
with named helper functions. The helpers carry comments explaining which
IEEE 754 semantics they preserve or discard.

## Magic constants

| CORE-MATH | PureLibm |
|-----------|----------|
| Bare hex literals (e.g. `0x1.921fb54442d17p-3`) | Same literal + comment citing Sollya script and generation command |

PureLibm requires every "magic" coefficient to include a comment tracing it
to its generation script in `coeff/`. The pattern is:

```c
/* Generated by: Sollya
 * Script: coeff/sinf.sollya
 * Command: remez(sin(2*pi*x), 5, [-2^-12, 2^-12]); */
static const double CR_SINF_C1 = 0x1.921fb54442d17p-3;
```

## Testing

| CORE-MATH | PureLibm |
|-----------|----------|
| Per-function `function_under_test.h` with three macros | Per-function test file using `exhaustive_driver.h` + `mpfr_oracle.h` |
| `check_exhaustive.c` with `doit()` | `purelibm_exhaustive_run_f32()` + `purelibm_check_one_f32()` |
| Type-punning unions in test code | `test_common.h` assertion helpers + `ieee754.h` bit conversion |
| `fenv_mpfr.h` with global `rnd` variable | `mpfr_oracle.h` with explicit rounding-mode parameter |
| OpenMP `#pragma omp parallel for` with `schedule(dynamic, 1)` | Same pattern in `exhaustive_driver.h` with `schedule(dynamic, 4096)` |

## Build integration

When compiling CORE-MATH source files directly (for consistency testing),
relaxed compile options are used (`PURELIBM_CORE_MATH_COMPILE_OPTIONS`):
`-Wconversion`, `-Wdouble-promotion`, `-Wshadow`, and `-Werror` are
omitted because CORE-MATH's coding style triggers them. Semantic flags
(`-fno-fast-math -ffp-contract=off`) are still applied.
